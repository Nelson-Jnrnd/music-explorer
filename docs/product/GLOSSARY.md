# Glossary of project terms

Canonical owner for words this project uses with a specific meaning. Add a term here **before** using it in `PROJECT.md`, issues, PRs, UI or messages to the Product Owner, and give its plain-language meaning in one sentence.

Rules (see `governance/USER_INTERACTION.md`):

- Prefer the ordinary word. Add a term only when no ordinary word fits and the concept recurs.
- One term per concept; list retired synonyms so they are not reintroduced.
- Terms for the Product Owner must be understandable without reading code. Internal technical names belong in `docs/architecture/`, not here.
- User-facing UI wording follows what users call things, which may differ from internal names. Record both when they differ.
